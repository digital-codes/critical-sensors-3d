# Design — orchard-thicket-leaf-calendar

## Context

The orchard view (`orchard/`, three.js + vite) renders real geodata: terrain
textured with a shadow-flattened DOP crop, ez-tree orchard trees at surveyed
positions, LoD2 buildings, OSM structures, seasonal grass and sky presets.
Season state is day-of-year driven; tree foliage variants are baked per
season keyframe. Config constants live in `src/config.ts` (single home,
admission rule in the file header); generated geodata in `src/site.json`
(regenerated by `tools/prepare_site.py`, never hand-edited).

This change documents three implemented visual features: the leaf-fall
calendar, the reflow-free season slider, and the thicket west of the
orchard. All are already implemented and verified through tag
`v0.8.4-orchard`; this change supplies the spec deltas.

## Goals / Non-Goals

- Goals: behaviour contracts for the leaf calendar, stable slider layout,
  and the thicket strip (placement, texture, snow exclusion).
- Non-Goals: individual tree rendering for the strip; new geodata
  generation; runtime-editable config (polygon is code-config, not UI).

## Decisions

### Leaf calendar via more season keyframes (not runtime interpolation)

Tree foliage variants are baked per keyframe
(`leaves.count = preset × leafFactor`); the nearest keyframe's variant is
shown, so anchor spacing is the visible resolution. The calendar is
therefore expressed as 8 keyframes (~2-week autumn steps: 274/290/305/320/
335) instead of interpolating leaf counts at runtime. Consequence: the
orchard generates 8 season variants per tree (generation time ~2×), which
the progress readout takes from the table length.

### Stable slider: fixed widths + tabular digits + zero-padded dates

The panel is a flex row; a growing date label ("· Vegetationsruhe") used to
push the slider under the pointer mid-drag. Fix: hard `width` on the label
element (232 px, `white-space: nowrap`, `font-variant-numeric:
tabular-nums`), zero-padded 3-digit day numbers through one shared
`seasonLabel()` formatter, keeping the existing 160 px slider width.

### Thicket: instanced blobs + traced polygon (no ez-tree)

The strip is too tight for individual trees. One `InstancedMesh` of
low-poly icosahedron blobs (~80 tris each, `flatShading`, cast+receive
shadow) covers it; placement is rejection-sampled inside
`CONFIG.THICKET.POLYGON` with a 5 m clearance from the orchard trees
(`site.trees`), seeded via `mulberry32` for determinism. The polygon's 8
vertices were georeferenced from the annotated screenshot: feature-matched
against DOP tile 32_455_5426 (scale 0.690 = 1/1.44 zoom, two-landmark
offset agreement), outline interior traced and simplified.

### Canopy texture: random aerial patches, not world-space projection

A world-XZ projection of the orthophoto onto the blobs was tried first and
rejected: it copies the terrain pixels, so blobs blend into the ground and
pick up gravel paths. Instead each instance carries an `aUvOff` instanced
attribute — a random UV offset rejection-sampled on dark-vegetation pixels
inside the polygon — and the standard material is patched via
`onBeforeCompile` to sample the aerial map at `vAuv + localPos.xz·k`
(~2.5 m of imagery per blob unit). Season tints are bright multiplier
casts (the texture carries the foliage colour; dark casts crushed the
mottling); winter stays dark grey.

### Snow exclusion by zeroing lawn-mask cells

The strip's bushes are green in the DOP, so the lawn mask included them and
the snow gate (lawn ∩ padded tree bounds) painted snow inside the strip.
`main.ts` zeroes the lawn-mask cells whose centres are inside the polygon
(5-point test with a 4-cell soft margin ≈ blob radius) while building the
terrain snow `DataTexture`. Grass blades are untouched (the strip keeps its
undergrowth look in summer).

## Risks / Trade-offs

- 8 baked season variants double generation time (~2×); acceptable for the
  view's use, progress text reports the count.
- The polygon is hand-editable in config; a bad polygon (self-intersecting)
  degrades sampling gracefully (ray-cast parity still terminates).
- The blob texture is summer imagery; winter realism relies on the tint
  cast, not on separate winter photography.

## Migration Plan

None — visual-only change, no data model impact. Config additions are
backwards compatible (new `THICKET` section, extended `SEASONS` table).
